# PDPA Data Leak Detection Lab

A home lab that detects Thai personal data (national ID numbers) leaving an
endpoint through a USB drive, an AI/web upload, or a PowerShell script, and
raises graded alerts in a SIEM. Built to understand how commercial DLP, SWG and
EDR products work inside, using open-source tools.

> **No real personal data.** Every ID in this project is generated by
> `datagen/generate.py`. None belongs to a real person.

## Result so far

Scanner scored on 1,000 synthetic files (403 with real-format IDs, 360 decoys
containing random 13-digit business numbers, 237 clean):

| Detection | False-positive files | ...that would page an analyst (high/critical) | Missed files | False IDs reported |
| --- | --- | --- | --- | --- |
| Regex only | 360 | 292 | 0 | 8,633 |
| Regex + Thai ID checksum | 270 | **0** | 0 | 750 (−91%) |

The checksum removes 91% of false matches. The rest are random numbers that
pass the check digit by chance (about 1 in 10); the severity threshold keeps
all of them at **low**, so no false positive reaches a high or critical alert.
Reproduce with `python -m datagen.generate && python -m datagen.evaluate`.

## How it works

```
Windows endpoint                         Ubuntu server
 user copies file ─► Python scanner ─►   Wazuh manager
   (USB / sync / web)  checksum + mask     decoders, rules, correlation
 Sysmon + Wazuh agent ───────────────►   dashboard
 browser ─► mitmproxy (mini SWG) ────►
```

| Lab component | Role | Commercial equivalent |
| --- | --- | --- |
| `scanner/` | Content inspection for Thai national IDs | DLP endpoint agent (e.g. Trellix DLP) |
| mitmproxy + cloud registry (Day 4) | Web traffic inspection, risk-rated destinations | SWG / CASB (e.g. Skyhigh) |
| Sysmon + Wazuh agent | Endpoint telemetry | EDR sensor (e.g. Trend Micro) |
| Wazuh manager | Log collection, rules, correlation | SIEM / management console |

Monitor mode only: the lab alerts, it never blocks. This mirrors how DLP is
rolled out in practice: tune in monitor mode until false positives are low,
then enable blocking.

## Severity

| Severity | Thai IDs in one file | Wazuh level |
| --- | --- | --- |
| low | 1–9 | 5 (logged only) |
| high | 10–49 | 10 |
| critical | 50+ | 12 (13 when FIM confirms) |

## USB scenario (Day 3, verified end to end)

Windows 11 VM, SanDisk USB stick passed through VirtualBox (xHCI + USB filter),
FAT32, drive `E:`. The watcher picks the stick up on its own
(`USB plugged in: watching E:\`). Alerts seen on the Wazuh manager:

| Copy to | File | Scanner | Wazuh rule | MITRE |
| --- | --- | --- | --- | --- |
| `E:\pdpa-nofim\` (no FIM) | 0994_pii.xlsx | critical, 120 IDs, usb | 100120, level 12 | T1052.001 |
| `E:\pdpa-test\` (FIM realtime) | 0092_pii.txt | high, 13 IDs, usb | 100111, level 10 | - |
| `E:\pdpa-test\` (FIM realtime) | 0996_pii.txt | critical, 60 IDs, usb | 554 then 100130, level 13 | T1052.001 |

Correlation (100130 USB, 100131 cloud sync) fires when FIM reports a file
added (rule 554) up to 120 s before a critical scan. Wazuh cannot compare the
FIM path with the scanner's `file` field, so the rule shows that a file was
added and a critical scan followed on the endpoint, not that both are the same file.

FAT32 has no ACL or owner. With FIM's default `check_all` the agent cannot
read permissions and drops the event without an error at normal log level.
The USB folder therefore uses `check_all="no" check_size="yes" check_mtime="yes" check_sum="yes"`
(see `wazuh/agent_ossec_snippet.xml`).

## Repository

```
scanner/thai_id.py      find, validate (check digit), mask
scanner/extract.py      text from .txt .csv .xlsx .docx (UTF-8 and TIS-620)
scanner/scan.py         scan a file or folder -> JSON event
scanner/watcher.py      watch sync folders + auto-detect USB drives
datagen/generate.py     synthetic test set with ground truth
datagen/evaluate.py     before/after scoring
wazuh/pdpa_rules.xml    custom Wazuh rules (levels, MITRE, correlation)
wazuh/agent_ossec_snippet.xml   agent config
docs/day1-setup.md      lab setup guide (Thai)
```

## Quick start

```bash
pip install -r requirements.txt
python -m pytest -q
python -m datagen.generate --out testdata --count 1000
python -m datagen.evaluate --data testdata
python -m scanner.scan testdata
```

On the Windows lab VM: copy `config.example.json` to `config.json`, edit the
paths, then `python -m scanner.watcher --config config.json`.
